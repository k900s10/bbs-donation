# Migrate donation infographic → Bun/React SPA, live Supabase data, deployed to Vercel

## Architecture (per bun.com/guides/deployment/vercel)
**Static SPA on Vercel; no serverless functions.** Your page is a public read-only transparency page and every Supabase query runs in the browser with the publishable key — a server adds nothing. This also sidesteps the documented Vercel limitation that Bun's runtime doesn't support HTML imports in routes (which `src/index.ts` relies on).
- **Local dev**: unchanged — `bun dev` (`Bun.serve()` + HMR).
- **Production (Vercel)**: `bun run build` bundles `src/**/*.html` → `dist/` (static JS/CSS/HTML, minified). `src/index.ts` is not part of the static build (it's not an HTML entrypoint), so it silently stays local-only.
- **Env vars on Vercel**: Bun inlines `process.env.BUN_PUBLIC_*` into the bundle at build time, so the two vars get set in Vercel Project Settings → Environment Variables. (If inlining doesn't trigger for any reference, the fix is one line in `build.ts`'s existing `define` block — verified during implementation.)
